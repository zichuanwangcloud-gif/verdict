# Verdict

发布验证台账：把「测试结论」挂在 **验收条件 × 提测版本** 上，新版本出来时自动判断哪些结论仍然有效、哪些被推翻需要重测，并给出「可发布 / 不可发布」的裁决。

## 分层

| 目录 | 职责 | 是否调用模型 |
|---|---|---|
| `internal/domain` | 业务对象：需求、验收条件、区域、变更集、证据、裁决 | 否 |
| `internal/ledger` | 证据有效性判定与裁决，纯函数 | 否 |
| `internal/verifier` | 验证器协议与内置验证器（`command`、`http`） | 否 |
| `internal/agent` | 起草验收条件、把变更映射到区域 | **是** |
| `internal/store` | SQLite 持久层 | 否 |
| `internal/api` | HTTP 接口 | 否 |
| `web` | Vue 3 + Vite 前端 | — |

纪律：除 `agent` 与各验证器的参数外，源码里不出现被测项目的技术名词。平台只认「区域」。

## 运行

```bash
# 后端（默认 127.0.0.1:8791，数据在 data/verdict.db）
go run ./cmd/server

# 前端开发（127.0.0.1:5191，/api 代理到后端）
cd web && pnpm install && pnpm dev

# 或构建后由后端直接托管
cd web && pnpm build      # 产物在 web/dist，后端启动时自动挂到 /
```

智能体凭据从环境读取（`ANTHROPIC_API_KEY` 等）。`VERDICT_MODEL` 覆盖模型（默认 `claude-opus-5-5`）；经自建网关转发且网关不认 `fallbacks` 字段时设 `VERDICT_NO_FALLBACK=1`。

⚠️ 接口没有认证，且 `command` 验证器会在本机执行命令。只监听本机，不要暴露到网络。

## 核心规则

验收条件在版本 M 上的证据，到版本 N 仍然有效，当且仅当 (M, N] 之间没有任何版本触碰它涉及的区域。没有声明区域的验收条件，任何后续版本都使其失效。

版本可发布，当且仅当每条「随版本发布」的需求至少有一条验收条件，且全部验收条件都有仍然有效的通过证据。

- 「关闭」处置直接豁免，尚未要求「关闭状态下无副作用」的证据
- 失败归因、基线管理、验证器自检（注入缺陷抽查）
- 智能体判定的双跑一致性检查与缓存
- 认证与多用户
